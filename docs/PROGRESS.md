## Phase 4 — Payments + receipts (2026-10-16)
- Landed: Migration `supabase/migrations/0004_phase4_payments.sql` (new file, no table changes) fixing a latent 1A bug and hardening the money RPCs — (1) `record_payment` was `SECURITY INVOKER` yet inserted/updated `public.receipt_counters`, which has only a SELECT policy → it could never succeed under `authenticated`; it is now `SECURITY DEFINER` with `search_path=public` and an explicit gym-ownership check (`current_gym_id()`), validating `amount_dzd > 0` (`INVALID_AMOUNT`), resolving `gym_id`/`member_id` from the subscription, and stamping `receipt_no` from the per-gym counter; (2) `record_payment` is replay-safe — a repeated client UUID returns the stored row and does NOT bump the counter (`DUPLICATE_REPLAY_OK`); (3) `edit_payment`/`delete_payment` are now `SECURITY DEFINER` (the 1A bodies could not update/delete: `authenticated` has no UPDATE/DELETE policy on `payments`), each enforcing `REASON_REQUIRED`, gym ownership (`RLS_DENIED` cross-gym), and writing `audit_log` old/new.
